# 周报生成技能

按固定任务分类大项归类本周工作，标注所属项目，优化表达后输出纯文本周报。纯指令规则，不依赖脚本，不生成文件。

## 固定分类

**任务分类大项（固定4类，按此顺序，跳过无内容项）：**
1. 模型开发和优化 — 训练、推理、调试、效果测试、版本发布
2. SDK开发和优化 — 后处理、逻辑重构、流程设计、SDK功能开发
3. 数据处理和优化 — 数据集处理、清洗、增强、负样本
4. 集成和测试问题修复 — Bug修复、问题排查、集成发版、技术协助

**参与项目（用于标注）：** ADAS前装车道线和斑马线、ADAS后装车道线和斑马线、其他项目

## 处理流程

1. **解析** — 识别日期行，移除条目序号前缀；多行子项合并为一条工作，保留完整逻辑
2. **归类** — 每条工作归入对应任务大项，相同任务合并；识别所属项目，工作内容前以 `【项目名】` 标注（前装→ADAS前装、后装→ADAS后装、跨项或不属→其他项目）
3. **优化** — 修正错别字（车俩→车辆、构件→构建、外界框→外接框）；口语改正式（效果接近→效果与预期基本一致、误检严重→误检率较高）；不改变原意，不臆造内容
4. **输出** — 纯文本，不生成文件

## 输出格式

```
==================================================
{年份}年第{周数}周工作周报
==================================================

时间：{YYYY-MM-DD}-{YYYY-MM-DD}

----------------------------------------
1、模型开发和优化
----------------------------------------
  1.1 【{项目名}】{工作内容}
  1.2 【{项目名}】{工作内容}
    - 步骤1
    - 步骤2

----------------------------------------
2、SDK开发和优化
----------------------------------------
  2.1 【{项目名}】{工作内容}

```

### 格式要点

- 大类别顺序固定，跳过无内容项，编号顺延
- 大类别用 `1、`（中文顿号），子项用 `1.1` 格式，**不用 `-` 或 `•`** 作主编号
- 子项前两个空格缩进，工作内容前以 `【项目名】` 标注
- **单条工作过长（含多步骤）时**：先一句话概括，再用换行 `-` 缩进排列各步骤（4个空格缩进），避免大段长句
- 大类别上下用 `-` 分隔，标题上下用 `=` 分隔

## 示例

输入：
```
/weekly-report
调试优化斑马线后处理逻辑，现在斑马线后处理逻辑改为：
1.通过findContours计算连通区域
2.过滤较小的异常区域
3.融合后的结果保留最大区域
```

输出（节选）：
```
----------------------------------------
2、SDK开发和优化
----------------------------------------
  2.1 【ADAS后装车道线和斑马线】调试优化斑马线后处理逻辑，重构后的处理流程为：
    - 通过findContours计算连通区域
    - 过滤较小的异常区域
    - 融合后的结果保留最大区域
```
