# 评测报告转微信文章

## 概述

将 llm-benchmark 生成的 Markdown 评测报告转换为微信公众号文章格式。文章遵循 tech-storytelling-style 的叙事风格，将技术评测写成读者友好的故事。

## 何时使用

- 已有 llm-benchmark 生成的评测报告（`reports/评测报告-*.md`）
- 需要将报告内容发布到微信公众号
- 想要按照 tech-storytelling-style 风格润色内容

**不使用**：直接发布原始报告时；不需要润色时。

## 使用方式

### 基本用法

```bash
# 自动查找最新的评测报告
/benchmark-to-wechat

# 指定报告文件路径
/benchmark-to-wechat --md reports/评测报告-20240101-sonnet.md
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--md` | 指定评测报告的 Markdown 文件路径 | `--md reports/评测报告-20240101-sonnet.md` |

**路径规则**：
- 支持相对路径（相对于项目根目录）
- 支持绝对路径
- 如果不指定 `--md`，自动查找 `reports/` 目录下最新的 `评测报告-*.md` 文件

## 核心工作流（4 步，严格按序）

### 1. 定位并读取报告

**如果指定了 `--md` 参数**：
- 直接读取指定路径的文件
- 验证文件存在且格式正确

**如果没有指定 `--md` 参数**：
- 扫描 `reports/` 目录
- 找到最新的 `评测报告-*.md` 文件（按文件名日期排序）
- 如果有多个文件，列出并让用户选择

**提取信息**：
- 测试日期、被测模型、测试方向、题目数量
- 每道题的**问题**和**回答**内容

### 2. 收集模型背景信息

询问用户或通过搜索获取：
- 模型厂商和发布时间
- 模型参数规模、上下文窗口等技术规格
- 模型定位和特点

**如果用户无法提供**：使用「信息未知」占位，不要臆造。

### 3. 生成微信文章

按以下结构生成文章，语言风格严格遵循 tech-storytelling-style：

#### 第一部分：模型登场

**目标**：用故事化方式介绍模型背景

内容要素：
- 厂商和发布时间（用时间锚点制造代入感）
- 模型定位（说人话，比喻优先）
- 核心参数（翻译成人话：参数规模=脑容量，上下文=短期记忆）
- 为什么值得关注（制造悬念）

**风格要求**：
- 用强画面词：登场、亮剑、祭出、杀入
- 比喻优先：「XX 亿参数，相当于人脑神经元的 X%」
- 设问推进：「问题来了：这个模型到底能不能打？」

#### 第二部分：测试前置声明

**目标**：交代测试背景和局限性

内容要素：
- 测试环境说明
- 测试方向和题目数量
- 关键免责声明（联网检索、输出不代表整体能力等）

**风格要求**：
- 短句起势：「先说结论：这是一次公平但有限的对决。」
- 口语化：「说白了，就是让 AI 做几道题，看它能得几分。」
- 不要用官方腔：删除「本次评测旨在...」之类的废话

#### 第三部分：实战演练

**目标**：展示每道题的问题和回答

内容要素：
- 每道题的**完整问题**（不要省略）
- 模型的**完整回答**（原样保留）
- 必要时用一句话点出亮点或槽点

**格式要求**：
- 问题用引用块或加粗显示，与回答区分
- 如果回答包含代码，保留代码格式
- 如果回答过长（>500字），考虑节选关键部分并标注「...」

**风格要求**：
- 过渡句要自然：「第一道题，是个硬骨头。」「接下来看看它怎么写代码。」
- 可以吐槽：「这回答...怎么说呢，至少态度端正。」
- 可以点赞：「这段解释，比很多人类写得都清楚。」
- 但不要每道题都点评，保持克制

#### 第四部分：赛后复盘

**目标**：总结测试结果，升华主题

内容要素：
- 整体表现评价（不要用「优秀/良好/及格」这种评分）
- 亮点和短板（用具体题目举例）
- 适用场景建议（说人话）

**风格要求**：
- 回扣开头：「还记得开头那个问题吗？现在可以回答了。」
- 价值落点：技术普惠、用户价值、行业意义
- 不要用「未来可期」「拭目以待」这种废话结尾
- 推荐结尾方式：一个问题、一个判断、一句吐槽

### 4. 处理格式转换

**HTML 转换为微信友好格式**：

如果原始报告包含 HTML，使用提供的转换脚本：

```bash
# 转换为 Markdown（推荐）
node skills/benchmark-to-wechat/scripts/html-to-wechat.ts input.html --output output.md

# 转换为内联样式的 HTML（微信兼容）
node skills/benchmark-to-wechat/scripts/html-to-wechat.ts input.html --format html --output output-wechat.html

# 从标准输入读取
cat input.html | node skills/benchmark-to-wechat/scripts/html-to-wechat.ts --stdin --output output.md
```

**脚本功能**：
- 自动转换 `<code>` 和 `<pre>` 为 Markdown 代码块（超过 50 行自动截断）
- 转换 `<table>` 为 Markdown 表格
- 转换 `<a>` 链接为脚注形式（文末统一列出）
- 转换 `<img>` 为 Markdown 图片语法
- 移除 HTML 标签，保留纯文本内容

**如果无法运行脚本**，按以下规则手动转换：
1. `<code>` 和 `<pre>` → 用 ``` 代码块包裹
2. `<table>` → 转为 Markdown 表格
3. `<img>` → 提示用户手动插入图片
4. `<a href>` → 保留链接，放在文末参考资料

## 禁止清单（与 tech-storytelling-style 对齐）

**废话开场白**：
- ❌ 「在 AI 飞速发展的今天...」
- ❌ 「随着大模型技术的成熟...」

**行业黑话**：
- ❌ 「赋能」「闭环」「抓手」「生态协同」
- ✅ 说人话：帮助、完整流程、关键点、大家一起做

**公式化结尾**：
- ❌ 「总之」「综上所述」「未来可期」
- ✅ 具体判断或问题收尾

**通稿腔**：
- ❌ 「该模型展现了强大的综合实力」
- ✅ 「这模型，能打。但别指望它场场 MVP。」

## 模板

生成文章时参考以下模板：

```markdown
# {标题：一句话抓住核心冲突或亮点}

{开头：用短句制造冲击，引出模型}

## 模型登场

{故事化介绍模型背景、参数、定位}

## 测试前置声明

{交代测试背景、局限性}

## 实战演练

### 第一题：{题目标题}

**问题：**
{完整问题}

**回答：**
{完整回答}

---

### 第二题：{题目标题}

{重复以上格式}

## 赛后复盘

{总结亮点、短板、适用场景}
```

## 常见错误

| 错误 | 修正 |
|------|------|
| 只有回答没有问题 | 必须同时展示问题和回答 |
| 使用官方腔调 | 按 tech-storytelling-style 改写 |
| 模型参数没有翻译成人话 | 用比喻解释：参数=脑容量，上下文=记忆 |
| 每道题都点评 | 保持克制，只在关键处点评 |
| HTML 格式未转换 | 按格式转换规则处理 |

## 输出示例

**标题**：「Claude 3.5 Sonnet：一个 AI 的期末考试」

**开头**：
2024 年 6 月，Anthropic 推出了 Claude 3.5 Sonnet。

官方说它「比上一代快两倍，成本只有五分之一」。

问题是：参数再漂亮，考试能不能过？

**模型登场**：
Sonnet 3.5，定位是「中杯」——比 Haiku 强，比 Opus 快。

翻译成人话：脑容量 XX 亿参数，短期记忆 XX 万 token。

说白了，就是个聪明但记性一般的选手。

**测试前置声明**：
先说结论：这是一次公平但有限的对决。

测试题库里有 8 道题，涵盖信息检索、代码编写和文章写作。

每道题都在独立的「小黑屋」里完成，防止作弊。

但要注意：一次测试不能说明一切。就像一次高考不能定义一个人。

**实战演练**：
第一道题，是个硬骨头。

**问题：**
{完整问题}

**回答：**
{完整回答}

这回答...怎么说呢，至少态度端正。

{继续其他题目}

**赛后复盘**：
还记得开头那个问题吗？「参数再漂亮，考试能不能过？」

现在可以回答了：能过，但别指望满分。

{具体亮点和短板}

这就是 AI 的现状：聪明，但还在学习怎么当一个靠谱的助手。
```

## 交付物

- 微信公众号文章（Markdown 或 HTML 格式）
- 保存路径：`reports/wechat-article-{YYYYMMDD}-{模型名}.md`
- HTML 转换脚本：`skills/benchmark-to-wechat/scripts/html-to-wechat.ts`

## 工具脚本

### html-to-wechat.ts

将 HTML 转换为微信友好的 Markdown 或内联样式 HTML。

**快速使用**：

```bash
# 转换为 Markdown
ts-node skills/benchmark-to-wechat/scripts/html-to-wechat.ts input.html --output output.md

# 转换为内联样式 HTML
ts-node skills/benchmark-to-wechat/scripts/html-to-wechat.ts input.html --format html --output output.html
```

**详细文档**：见 `skills/benchmark-to-wechat/scripts/README.md`
